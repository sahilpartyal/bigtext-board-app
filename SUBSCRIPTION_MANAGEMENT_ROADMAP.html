Subscription Management System

A comprehensive guide to managing Pro and Free users professionally in BigText app

📱

Current Architecture Overview

Your app currently uses a simple but effective approach for managing subscription status.

Device (Local)

SharedPreferences stores isPro flag locally on each device

App Store / Play Store

Apple/Google stores purchase history linked to user's account

Backend (Optional)

Not required for basic implementation but useful for advanced features

💡
Key Insight

Apple and Google act as your purchase database. You don't need to build user authentication or store purchase records - they handle everything.

🔄

How User Identification Works

Purchase Flow

1

User Initiates Purchase

User taps "Subscribe" button in your app

2

Store Handles Payment

Apple/Google handles payment, authentication, and receipt generation

3

App Receives Confirmation

Your app receives purchase confirmation via in_app_purchase plugin

4

Save Status Locally

App saves isPro=true to SharedPreferences for quick access

Restore Flow (Different Device)

1

User Installs App

Fresh install on new device, isPro defaults to false

2

User Taps "Restore Purchases"

App calls InAppPurchase.instance.restorePurchases()

3

Store Verifies Account

Apple/Google checks if this Apple ID/Google Account has past purchases

4

Purchases Restored

App receives list of past purchases, updates isPro=true locally

Implementation Code

// 1. Add dependency
dependencies:
  purchases_flutter: ^6.0.0

// 2. Initialize on app start
await Purchases.configure(
  PurchasesConfiguration('your_api_key')
);

// 3. Check subscription status anywhere
final customerInfo = await Purchases.getCustomerInfo();
final isPro = customerInfo.entitlements.all['pro']?.isActive ?? false;

// 4. Make a purchase
try {
  final offerings = await Purchases.getOfferings();
  final package = offerings.current?.monthly;
  await Purchases.purchasePackage(package!);
} catch (e) {
  // Handle error
}

// 5. Listen for changes (auto-updates on renewal/expiry)
Purchases.addCustomerInfoUpdateListener((info) {
  final isPro = info.entitlements.all['pro']?.isActive ?? false;
  // Update UI
});

Subscription Data Model

Here's the data structure for a professional subscription system:

class UserSubscription {
  // User Identification
  final String? appUserId;        // RevenueCat anonymous ID
  final String? customUserId;    // Your user ID (optional)

  // Subscription Status
  final SubscriptionStatus status; // active, expired, trial, etc.
  final String? productId;       // monthly, yearly, lifetime
  final DateTime? expiresAt;    // When subscription ends
  final DateTime? purchasedAt;  // When first purchased

  // Subscription Details
  final bool willRenew;         // Auto-renewal enabled?
  final bool isTrial;           // Currently in trial?
  final String store;           // app_store, play_store

  // Computed Properties
  bool get isPro => status == SubscriptionStatus.active;
  bool get isExpiringSoon =>
    expiresAt?.difference(DateTime.now()).inDays < 3 ?? false;
}

Subscription Status States

Status Description User Access
active Paid subscription is active Full Pro Access
trial In free trial period Full Pro Access
grace_period Payment failed, in grace period Full Pro Access
expired Subscription ended Free Only
cancelled Will not renew (still active until period ends) Full Pro Access
refunded User got a refund Free Only

Best Practices & Tips

1
Always Validate Receipts

Never trust client-side purchase confirmations alone. Use server-side validation or RevenueCat.

2
Handle Edge Cases

Network failures, pending purchases, family sharing, refunds - test all scenarios.

3
Cache Status Locally

Store isPro locally for fast UI rendering. Update from source periodically.

4
Graceful Degradation

If purchase check fails, default to cached status. Don't lock users out unnecessarily.

5
Clear Restore Option

Make "Restore Purchases" easily findable. Apple requires this for app approval.

6
Test on Real Devices

Simulator testing is limited. Use sandbox accounts on real devices before release.
