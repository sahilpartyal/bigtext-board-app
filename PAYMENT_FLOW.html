BigText — Complete Payment Process

How a user pays for BigText Pro, end to end: from the upgrade banner to Pro being unlocked on device. Traced from the Flutter source in lib/.

1. The short version

BigText does not process payments itself. There is no server, no card form, no Stripe/Razorpay. All money moves through the platform store — Apple StoreKit Google Play Billing — via the in_app_purchase: ^3.2.0 Flutter plugin.

The app's only jobs are: (1) show the plans, (2) ask the store to open its native payment sheet, (3) listen for the store's result, and (4) write isPro = true into SharedPreferences on the device so features unlock and ads switch off.

2. What is actually sold

Three products, defined once in lib/utils/constants.dart (class ProductIds) and mirrored in ios/Products.storekit for local StoreKit testing.

PlanProduct IDStore typePrice shown in app
Monthlybigtext_pro_month_Auto-renewing subscription (group bigtext_pro_group)$0.99 / month
Yearly BEST VALUEbigtext_pro_year_Auto-renewing subscription$9.99 / year — "Save 16%" (calculated from the monthly price)
Lifetimebigtext_pro_lifetimeNon-consumable (one-time)$19.99 once

The same IDs are used on both platforms — _monthlyIos and _monthlyAndroid hold identical strings, so the platform getters are effectively decorative today.

Two ID details worth checking before release. The subscription IDs end in a trailing underscore (bigtext_pro_month_, bigtext_pro_year_). That looks like a leftover from naming, but it must match App Store Connect / Play Console exactly or queryProductDetails returns them in notFoundIDs and the buy button fails with "Product not found".

5. What Pro actually changes

Everything gates off the four SharedPreferences keys written in step 8:

KeyTypeWritten / read by
isProboolThe single source of truth. Read by SubscriptionNotifier._loadInitialState(), by AdProvider on every ad decision, and by main() at launch.
subscriptionTypeStringfree | monthly | yearly | lifetime.
subscriptionProductIdStringThe purchased store ID.
purchaseDateISO‑8601 StringWritten but not currently used for anything.

Ads switch off

Free: banner + interstitial every N actions. Pro: AdProvider reads isPro and skips initialization entirely; onUserBecamePro() disposes live ads. main() won't even call AdService().init() for a Pro user.
lib/providers/ad_provider.dart:106-116, 199 · lib/main.dart:27-30

Limits lift

FreeTierLimits → ProTierLimits: fonts 4→12, colors 6→15, recent messages 10→50, custom logo false→true.
lib/utils/constants.dart:88-106

Feature checks

canUseFeature(ProFeature.…) returns true for everything when isPro. Note: Business and Presentation modes are already free (canUseBusinessMode = true), even though the paywall lists them as Pro features.

6. Restore purchases

Needed for reinstalls, new devices, and required by App Review for non-consumables.

restore()  →  _iap.restorePurchases()
           →  wait 2 seconds for purchaseStream events
           →  each event arrives as PurchaseStatus.restored
           →  _verifyPurchase → _deliverProduct → isPro = true
           →  if nothing came back: error "No purchases to restore"

The 2-second wait is a timing heuristic rather than a real completion signal (purchase_service.dart:176-212). On a slow connection a legitimate restore can land after the timeout, so the user sees "No purchases to restore" and then silently becomes Pro a moment later.

7. Test mode — the free-Pro switch

Guard this constant on every release. kTestPurchaseMode at purchase_service.dart:12. When true, buy() never contacts the store: it waits one second, writes isPro = true, and returns success. Ship that and every user gets Pro for free.

Current value in this checkout: false — correct for production. This requires the Paid Apps Agreement to be active and all three products approved, otherwise the store returns an empty catalog and buy fails.

8. Gaps in the current flow

Things a reviewer or a determined user will find. Listed roughly by impact.

No server-side receipt validation

_verifyPurchase() trusts the client (purchase_service.dart:277-286, with a TODO saying as much). Anyone who can write to SharedPreferences — a rooted/jailbroken device, or a restored backup from a Pro device — gets Pro. Fixing it means posting purchase.verificationData.serverVerificationData to a backend that calls Apple's verifyReceipt / Google's Play Developer API.

Subscriptions never expire on device

isPro is a permanent local boolean. Nothing reads purchaseDate, no expiry is stored, and there is no renewal or cancellation check. A user who buys one month of Pro and cancels keeps Pro forever as long as they don't reinstall. The comment at purchase_service.dart:303-304 acknowledges the missing expiry handling.

Prices are hardcoded in the UI, not read from the store

_buildPlanCards() and _buildCTAButton() hardcode $1.99 / $14.99 / $29.99 (subscription_screen.dart:203-308) even though PurchaseService.getPrice() exists and returns the store's localized string. Consequences: wrong currency for non-US users, and prices that silently diverge from App Store Connect. The upgrade bottom sheet already disagrees — it advertises "from $0.99/mo" (upgrade_bottom_sheet.dart:113) against an actual $1.99 monthly.

Required subscription legal text is missing

_buildLegalText() returns an empty SizedBox (subscription_screen.dart:352-354). Both stores require auto-renew terms plus links to Terms and Privacy Policy on the paywall; App Review rejects subscription paywalls without them.

Smaller items

  • Feature lists disagree across surfaces — the bottom sheet promises "custom logo upload" and "12 colors", the paywall says "All colors + custom" and 12 fonts, while ProTierLimits.maxColors is 15.
  • Business/Presentation modes are sold as Pro but are free in code (constants.dart:93-94).
  • _wasNotPro is set in a post-frame callback; an already-Pro user reopening the paywall can't accidentally trigger the success redirect, but a purchase completing before that callback runs would be missed.
  • A canceled purchase clears the spinner without calling onPurchaseError, so the paywall shows no feedback — intentional, but worth knowing when debugging "nothing happened".
  • prodInterstitialAndroid is an empty string (constants.dart:16) — unrelated to payments, but it means Android interstitials are broken for free users.
